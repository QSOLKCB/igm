# IGM Validation Ladder

## Foundational invariant

> **Perfect Mathematics Does Not Equal Perfect Biological Reality.**

Validation is deliberately layered so that strong computational evidence cannot silently become a stronger biological or clinical claim.

```text
mathematical correctness
    != computational correctness
    != biological validity
    != clinical validity
```

## V0 — Synthetic / schematic

A V0 profile is useful for software engineering, algorithm development, visualisation, performance work and interface design.

Requirements:

- assumptions are explicitly labelled;
- no claim that geometry represents a validated IgM conformation;
- synthetic fixtures are identified as synthetic;
- deterministic/reproducible execution may be tested;
- no biological promotion from runtime success.

Typical examples:

- idealized five-sector assembly;
- arbitrary bounded hinge ranges for testing;
- synthetic coordinates;
- vortex-inspired coordinates used solely as a parameterization.

## V1 — Source-informed

A V1 profile includes biologically meaningful parameters derived from traceable public or appropriately governed sources.

Requirements:

- source registry entries exist;
- source identifiers are resolvable;
- every material parameter identifies provenance/status;
- unsupported degrees of freedom remain assumed/unknown;
- transformations from source to model are documented;
- source limitations are preserved.

V1 means **source-informed**, not validated biology.

## V2 — Computationally reproduced

A V2 model has reproducible implementation evidence.

Requirements:

- independent implementation or reference path exists where appropriate;
- deterministic or statistically reproducible output criteria are declared;
- accelerator residual tolerances are explicit;
- repeated runs are recorded;
- coverage/completeness checks pass;
- failed/rejected runs are not silently discarded;
- exact source/profile/runtime versions are recorded.

V2 can establish that implementations agree under the declared model. It cannot establish that the model is biologically correct.

## V3 — Externally calibrated

V3 requires comparison against external structural, biochemical or experimental observations that were not merely generated by the same model.

Requirements should include, as appropriate:

- predefined calibration targets;
- independent external observations;
- uncertainty handling;
- quantitative goodness-of-fit/residual reporting;
- separation of calibration and evaluation data where possible;
- negative/failed calibration results preserved;
- qualified interpretation of what calibration supports.

Promotion to V3 is a research judgement. Automation may compute metrics, but must not make the scientific promotion by itself.

## V4 — Independently validated research model

V4 is reserved for a model whose relevant claims have been independently evaluated by qualified researchers using an appropriate research protocol.

Possible requirements include:

- independent team or dataset;
- predefined validation criteria;
- relevant ethics/governance approvals where humans/data are involved;
- reproducible methods and accessible evidence;
- publication or equivalent scientific review where appropriate;
- documented limitations and failure envelope.

V4 still does **not** automatically mean clinical validity, medical-device approval, or suitability for patient care.

## Clinical/regulatory status is separate

Do not add `V5 = clinical`.

Clinical validity, clinical utility, medical-device conformity, ARTG inclusion, quality-system compliance and institutional approval are separate dimensions governed by their own requirements.

A model can be V4 and still be unsuitable or unlawful for clinical use.

## Model/report metadata

Every model and accepted result should eventually carry:

```json
{
  "validation_level": "V0|V1|V2|V3|V4",
  "biological_validity_claimed": false,
  "clinical_validity_claimed": false,
  "medical_device_claimed": false,
  "evidence": []
}
```

Stronger boolean claims must never be inferred solely from `validation_level`.

## Promotion rule

Promotion must be monotonic in evidence, not confidence language.

For example:

```text
V1 + more enthusiastic prose != V2
V2 + more GPUs != V3
V3 + a pretty figure != V4
```

Each promotion requires evidence specific to the next level.
